# 数学建模：文献检索与论文拆解 Skills

两个独立、可衔接的中文技能：帮助把题目转成检索问题，再把找到的论文读成可理解、可评估的建模思路。

| Skill | 负责什么 | 默认工作方式 |
|---|---|---|
| [数模文献检索教练](skills/modeling-literature-search/SKILL.md) | 拆题、关键词、递进检索、题名摘要初筛 | 你操作知网；助手每轮给当前操作，依据反馈决定下一步 |
| [数模论文拆解](skills/modeling-paper-dissection/SKILL.md) | 思路、模型分工、关键公式、求解过程、效果证据、可迁移部分 | 读取你提供的论文；先整体思路，再关键细节；支持单篇和多篇 |

## 使用示例

检索：

```text
请用 $modeling-literature-search 帮我拆这道数学建模题。
我自己操作知网，你每次只给当前一轮的搜索方案。
[粘贴题目；如有已有结果，也一起提供]
```

已有结果：

```text
请用 $modeling-literature-search 筛选下面这些题名和摘要，
判断哪些值得下载；已有信息足够时直接进入阅读，不必重新搜。
```

论文拆解：

```text
请用 $modeling-paper-dissection 拆解附件论文。
讲清楚它解决什么问题、各个模型如何连接、怎么求解、
效果在哪些条件下成立，以及可以借鉴什么。
[有赛题时可以一并提供；没有也能读论文]
```

多篇比较：

```text
请用 $modeling-paper-dissection 先分别拆解这几篇论文，
再比较方法思路、数据要求、验证证据和对本题的适配性。
不同数据集上的误差不要直接排名。
```

## 两者如何衔接

检索端交给阅读端：子问题、已知数据与约束、候选论文及选择理由、希望原文回答的问题。

阅读端交回检索端：未解决的问题、原文位置、为什么影响建模选择、已知关键词及需要的证据。

两个技能均可单独使用，另一个未安装时仍可输出交接信息。

## 设计边界

- 不自动操作知网，不需要浏览器自动化、API密钥或Zotero。
- 不强制每个题都经过全部检索轮次；找到有用论文就读。
- 覆盖预测、优化、评价、分类和机理/仿真；不套固定模型清单。
- 论文拆解保留原文依据，区分作者报告与助手分析。
- 无本题实验结果时只给候选路线，不编造模型精度排名。
- 默认在对话中交付，不自动生成Excel、代码或长报告文件。

## 文件结构与使用方式

每个 `skills/<名称>/` 都是完整技能目录，包含 `SKILL.md`、中文界面元数据 `agents/openai.yaml` 和按需读取的 `references/`。在支持目录型技能的环境中导入整个目录，保留相对路径。保存到GitHub本身不等于在每个客户端自动安装。
